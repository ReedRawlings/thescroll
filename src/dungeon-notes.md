# Demo floor and assets

`generateDungeon(seed, floor)` builds a reproducible 19×25 floor from four open room prefabs, with a cycle of safe corridors. It returns walkability as `tiles[y][x]` (0 wall, 1 floor), integer tile coordinates, room-scoped enemy placements, stairs outside the entrance, and a treasure chest. `roomAt` returns null in corridors. `pathfind` uses four-direction BFS and excludes the starting tile; an empty route means already there or unreachable. The third demo floor introduces a boss in the stairs room. This is a demo exception to the design's eventual boss cadence of floors 10/20/30/40.

Enemies begin off the center corridor axes so normal encounters remain avoidable. Chase confinement must use `roomId`; the exploration controller owns movement and removal after battle. All four rooms and every walkable tile are connected for 300 tested seed/floor combinations. The full map fits 342×450 pixels at tile size 18.

`ASSETS` is an array suitable for `load.image(key,url)` or `load.spritesheet(key,url,{frameWidth,frameHeight})`. URLs are relative to the site base so deployment under a subdirectory works. Hero frames 0–11 are the supplied 16×18 Mage idle cycle; torch frames 0–5 are 16×18. All remaining entries are single textures. RpgMix actor images were trimmed to their transparent bounding boxes (no resampling) for predictable display sizing. Terrain crops are 16×16; stairs is a 48×16 strip and can be displayed at 28×18 or 36×18. Keep pixel-art sampling nearest-neighbor.

Sources: supplied `Assets/MiniRogue Dungeon Premium` (Mage, dungeon tile crops, chest, yellow torch) and supplied `Assets/RpgMix/actor/monster` (miniflam/original + blue variant, slime, electric_bat, skeleton, goblin_king). Assets are curated copies/crops of the user's bundled artwork, not newly generated art. No license/readme files were found in the supplied asset directories; this demo does not claim a new license or redistribute the source packs. Only the selected runtime PNGs are included in `public/assets`.
